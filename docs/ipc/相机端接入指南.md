# 相机端接入指南（FRAME ring 生产者）

- 读者：相机采集端开发团队
- 协议权威文档：[SHM_PROTOCOL.md](SHM_PROTOCOL.md)（本文内联了开工所需全部内容）
- 交付阶段：Phase 4（Phase 3 过渡期**无需任何改动**，见 FAQ-1）

## 1. 你在这一架构里的职责

```
你的程序(采集进程) ──写帧──> Local\IAP_SHM_FRAME_V1 (8槽环形) ──> 分析端 / 孪生端 / 归档
```

你是**唯一的 FRAME 生产者**：从相机 SDK 拿到每帧图像后，按协议写入环形缓冲并通知消费者。你不关心分析和显示——写完即走，永不等待任何下游。

Phase 3 过渡期间由我们的文件桥接进程代写；Phase 4 你用 IKapLibrary SDK 的采集回调替换它，链路上最后一段"存图编码"随之消失，实现 Camera DMA → 共享内存直达。

## 2. 五条核心规则（先记住这个，再看代码）

1. **完成判据是 `seq`，不是 status**：数据写完 → 最后一步才写 `slot.seq`（完成标记）→ 再更新 `CTRL.frame_write_seq` → `SetEvent`。顺序绝不能乱；
2. **槽定位**：`slot_index = seq % 8`（seq 从 1 递增，永不回零）；
3. **永不阻塞**：环满了直接覆盖最旧槽（`dropped_by_overwrite++`），绝不能等待消费者；
4. **心跳**：每轮写帧前更新 `producer_heartbeat_ms`（10s 无心跳下游判你离线）；
5. **单生产者互斥**：启动时抢 `Local\IAP_PRODUCER_MUTEX`；抢不到说明桥接进程/另一实例在跑，只读模式或退出。

## 3. 写一帧的完整时序

1. 更新 `producer_heartbeat_ms`（CTRL 偏移 56，u64）；
2. `next = frame_write_seq + 1`；`slot = next % 8`；`slot.status = 1`；
3. 像素数据（GRAY8，行对齐 = width=31901）写入 slot 偏移 64；填 `data_bytes`(=31,901,000)、`timestamp_ns`、`frame_id`、`crc32`；
4. `slot.seq = next`；`slot.status = 2`；
5. `CTRL.frame_write_seq = next`；
6. `SetEvent(Local\IAP_EVT_FRAME)`。

帧尺寸/格式变化（GRAY16、换分辨率）：新建 CTRL 值并按 `w×h×bpp+64B` 上取整到整 MB 重算槽尺寸——务必与分析端约定停机窗口，禁止运行中热改。

## 4. C# 参考骨架

```csharp
using System;
using System.IO.MemoryMappedFiles;
using System.Threading;

const long FrameSlots = 8, FrameSlotBytes = 37748736, W = 31901, H = 1000;

var mutex = new Mutex(false, @"Local\IAP_PRODUCER_MUTEX");
if (!mutex.WaitOne(0)) throw new Exception("已有生产者在运行（桥接进程或另一实例）");

var ctrl = MemoryMappedFile.CreateOrOpen(@"Local\IAP_SHM_CTRL_V1", 4096);
var frame = MemoryMappedFile.CreateOrOpen(@"Local\IAP_SHM_FRAME_V1", FrameSlots * FrameSlotBytes);
var evtFrame = EventWaitHandle.TryOpenExisting(@"Local\IAP_EVT_FRAME",
        out var existing) ? existing
        : new EventWaitHandle(false, EventResetMode.ManualReset, @"Local\IAP_EVT_FRAME");

using var ctrlSeq = ctrl.CreateViewAccessor(40, 8);        // frame_write_seq
using var ctrlBeat = ctrl.CreateViewAccessor(56, 8);       // producer_heartbeat_ms

void PublishFrame(ReadOnlySpan<byte> gray, ulong frameId)
{
    long seq = (ulong)ctrlSeq.ReadUInt64(0) + 1;
    long slotOff = (seq % FrameSlots) * FrameSlotBytes;
    using var slot = frame.CreateViewAccessor(slotOff, FrameSlotBytes);

    ctrlBeat.Write(0, (ulong)Environment.TickCount64);     // 1. 心跳
    slot.Write(32, 1u);                                    // 2. status=writing
    slot.WriteArray(64, gray.ToArray(), 0, (long)(W * H)); // 3. 数据(可改用指针写)
    slot.Write(28, (uint)(W * H));                         //    data_bytes
    slot.Write(16, frameId);                               //    frame_id
    slot.Write(8, DateTime.UtcNow.Ticks);                  //    timestamp_ns(换算)
    slot.Write(24, Crc32(gray));                           //    crc32
    slot.Write(0, (ulong)seq); slot.Write(32, 2u);         // 4. seq=完成标记
    ctrlSeq.Write(0, (ulong)seq);                          // 5. 全局序号
    evtFrame.Set();                                        // 6. 唤醒
}
```

（骨架省略 CRC32 实现与单位换算；接入时以 SHM_PROTOCOL.md 字段表为准。）

## 5. Python 参考骨架（IKapLibrary SDK 回调模式）

```python
import ctypes
k32 = ctypes.windll.kernel32

def open_or_create_mapping(name: str, size: int) -> int:
    PAGE_READWRITE, FILE_MAP_ALL_ACCESS = 0x04, 0xF001F
    h = k32.CreateFileMappingW(ctypes.c_void_p(-1), None, PAGE_READWRITE,
                               0, size, name)
    return h

def publish(gray_ndarray, frame_id, h_frame, h_evt, ...):
    # gray_ndarray: np.uint8 (H, W)，来自 SDK 帧回调
    seq = read_u64(ctrl, 40) + 1
    slot = (ctypes.c_ubyte * SLOT_BYTES).from_address(
        base_frame + (seq % SLOTS) * SLOT_BYTES)
    write_heartbeat()
    write_bytes(slot, 64, gray_ndarray.tobytes())   # 或 ctypes.memmove 零中间拷贝
    fill_meta(slot, seq, frame_id, crc32(gray_ndarray))
    write_u64(slot, 0, seq)        # 4. seq 最后写
    write_u64(ctrl, 40, seq)       # 5. 全局序号
    k32.SetEvent(h_evt)            # 6.
```

SDK 侧对齐 IKapLibrary 的 `Examples\Python\IKapCPythonNp`（GrabContinuous 帧回调）与 `Examples\C\GigEVisionBoard`；若回调只给副本，多一次 32MB memcpy（≈10ms）完全可接受。

## 6. 联调与验收

| 项 | 标准 |
|---|---|
| 自测 | 你的生产者 + 我们的 `tools/shm_inspect.py`：能 dump 出帧、seq 递增、CRC 抽查通过 |
| 时延 | SDK 回调 → `SetEvent` ≤ 100ms（含一次 32MB 拷贝） |
| 稳定性 | 1fps×32MB 连续 30min，零崩溃、`dropped_by_overwrite` 增长符合预期 |
| 接管 | 杀掉进程重启后 seq 继续递增，下游无感恢复 |

## 7. FAQ

1. **过渡期（Phase 3）我们要做什么？** 什么都不用做。IKapExpert 照常存图，我们的桥接进程代写 ring。你们只在做 Phase 4 时读本指南。
2. **分析端还没起，我能先写吗？** 能。ring 是你的，消费者来不来都不影响你写。
3. **消费者读得太慢怎么办？** 不归你管。覆盖最旧槽即可，这是设计意图（latest-wins）。
4. **为什么不用 `Global\` 命名？** 需要特权，服务/会话混合场景才需要；本方案三端同会话，`Local\` 足够。
5. **能直接用 DMA 写进共享内存吗？** 取决于 IKap SDK 是否暴露用户缓冲区；有就最好，没有就一次 memcpy，协议不感知。
