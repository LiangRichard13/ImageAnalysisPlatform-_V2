# 孪生系统端接入指南（FRAME + RESULT 只读消费者）

- 读者：孪生数字界面开发团队（Qt/原生桌面）
- 协议权威文档：[SHM_PROTOCOL.md](SHM_PROTOCOL.md)（本文内联了开工所需全部内容）

## 1. 你在这一架构里的职责

```
Local\IAP_SHM_FRAME_V1  (原始帧, 8×36MB)  ──┐
                                            ├─只读 latest-wins──> 你的界面显示
Local\IAP_SHM_RESULT_V1 (检测结果, 8×64MB) ──┘
```

你是**纯只读消费者**：永远不写任何共享内存（CTRL 里的 `twin_heartbeat_ms` 可选更新除外）。你同时订阅两条 ring：FRAME 上的最新原始帧保证实时画面，RESULT 上的最新检测结果叠加异常标注。分析推理慢（秒级）时结果自然滞后于画面——两条链路独立，互不拖累。

## 2. latest-wins：为什么不是"一帧不落"

生产速度（1fps）可能快于你的渲染，分析更慢于生产。协议设计为**各消费者永远取最新完成帧**：跳过的帧视为主动丢弃（`dropped_by_lag` 计数），不排队、不补偿。你不需要处理积压、不需要 ACK。

## 3. 读取流程（两条 ring 相同）

1. 等待事件 `Local\IAP_EVT_FRAME` / `IAP_EVT_RESULT`（超时 50ms；超时后照常走一遍下面的流程作兜底轮询）；
2. `s = CTRL.frame_write_seq`（偏移 40）或 `result_write_seq`（偏移 48）；`s==0` 或与上次相同 → 本轮结束；
3. `slot = s % 8`；先读 slot 头部 `seq`（slot 偏移 0）：≠ `s` → 数据被覆盖，直接回步骤 2 追最新；
4. 读取数据（见 §4 的零拷贝约束）；
5. 复读 slot 偏移 0 的 `seq`：≠ `s` → 读取期间被覆盖，丢弃本次回步骤 2；
6. 若已追平（`s` == 当前全局 seq）→ `ResetEvent`。
7. （可选）写 CTRL 偏移 80 `twin_heartbeat_ms`。

源离线判定：CTRL 偏移 56 的 `producer_heartbeat_ms` 距当前超过 10s → 显示"源离线"；恢复后 seq 继续递增，无需重连逻辑。

## 4. 图像数据的零拷贝与生命周期

- 原始帧：GRAY8，`w×h` = 31901×1000，行对齐 = width（无 padding）；
- 预测标注图 `pred`：GRAY8 全分辨率（slot 偏移 64+8192 起，长度 `pred_bytes`）；
- 热力图 `heat`：GRAY8 **全分辨率异常强度图（未上色）**，紧随 pred 之后（长度 `heat_bytes`）。上色由你做，等效映射：
  `cv2.applyColorMap(heat, cv2.COLORMAP_JET)`——与历史归档 PNG 颜色一致（注意 OpenCV 输出为 BGR，转 Qt 时翻转为 RGB）；
- 结果 JSON：slot 偏移 64 起 `json_bytes` 字节，字段与现行 `output/{id}.json` 一致（含 `anomaly_level`、`analog_voltage` 等）；
- **零拷贝约束**：直接 wrap 共享内存的 QImage 必须在下一帧写入同一 slot 前（≥1 秒，裕量充足）结束引用并释放；做不到就 memcpy 一份（32MB ≈ 10ms）再显示，语义不变；
- 构造 QImage 时**显式传 bytesPerLine = width**（GRAY8 无行 padding，与 Qt 默认的 4 字节对齐假设不同）。

## 5. PyQt 参考骨架

```python
import ctypes, numpy as np
import cv2
from PyQt5.QtGui import QImage
k32 = ctypes.windll.kernel32

# attach（一次性）
h = k32.OpenFileMappingW(0xF001F, False, "Local\\IAP_SHM_FRAME_V1")
base = k32.MapViewOfFile(h, 0xF001F, 0, 0, 8 * 37748736)
h_evt = k32.OpenEventW(0x001F0003, False, "Local\\IAP_EVT_FRAME")  # EVENT_ALL_ACCESS

def wait_and_get_latest():
    k32.WaitForSingleObject(h_evt, 50)
    s = read_u64(ctrl_base, 40)                 # frame_write_seq
    if s == 0 or s == last_seen: return None
    slot = base + (s % 8) * 37748736
    if read_u64(slot, 0) != s: return None      # 被覆盖
    w, hgt = 31901, 1000
    arr = np.frombuffer((ctypes.c_ubyte * (w*hgt)).from_address(slot+64),
                        dtype=np.uint8).reshape(hgt, w)
    img = QImage(arr.data, w, hgt, w, QImage.Format_Grayscale8)
    # ...渲染；img/arr 生命周期须在本函数返回前结束（或先 arr.copy()）
    if read_u64(slot, 0) != s: return None      # 读取期间被覆盖
    if s == read_u64(ctrl_base, 40): k32.ResetEvent(h_evt)
    return s

def to_jet_rgb(heat_u8: np.ndarray) -> np.ndarray:
    return cv2.applyColorMap(heat_u8, cv2.COLORMAP_JET)[:, :, ::-1]  # BGR→RGB
```

Qt C++ 等价路径：`OpenFileMappingW` → `MapViewOfFile` → `QImage(static_cast<const uchar*>(slotPtr+64), w, h, w, QImage::Format_Grayscale8)`；事件用 `QWinEventNotifier` 包 `OpenEventW` 句柄驱动信号槽（或独立线程 `WaitForSingleObject`）。

## 6. 验收标准

| 项 | 标准 |
|---|---|
| 时延 | 帧就绪（`SetEvent`）→ 界面可显示 ≤ 100ms |
| 稳定性 | 1fps×32MB 连续 30min 无崩溃、无花屏（CRC 抽查 + 目视） |
| 伪彩一致性 | 热力图 JET 上色与归档 `_heatmap.png` 逐像素同色 |
| 离线/恢复 | 生产者停 10s 显示"源离线"，重启后自动续流，无需人工干预 |

## 7. FAQ

1. **为什么我 ResetEvent 之后还收到旧事件？** 事件只是唤醒提示，正确性永远以 `seq` 为准（协议 §6）；
2. **过渡期没有实时链路怎么办？** 归档目录（现行 `input/`、`output/` 结构）持续存在，可先读文件再切实时，两路并行验证；
3. **能不能两个画面分别订阅两条 ring？** 可以且建议：原始帧走高频渲染，结果走"最新有就换"，互不阻塞；
4. **32 位程序行吗？** 不行，800MB 映射必须 64 位进程。
